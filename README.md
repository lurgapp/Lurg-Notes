# Lurg Notes

Исходный код Lurg Notes, подготовленный для отдельного публичного репозитория. Включены текущий Android-клиент 0.5.4, сервер заметок с необходимыми общими компонентами Lurg, шлюз синхронизации и продуктовая страница.

Редактор использует Kotlin, Jetpack Compose и локальную базу Room. Текст хранится в Markdown; облачные документы шифруются на устройстве по протоколу E2EE v2. AI и добавление фактов в Graph запускаются пользователем явно.

## Состав

| Папка | Содержимое |
| --- | --- |
| `android/` | Текущий нативный клиент: редактор, локальные данные, E2EE, HTTP/LCP sync, Lurg ID, Graph, FCM, обновления, ресурсы и тесты. |
| `server/` | Notes API и его зависимости: авторизация, AI, Graph, push, outbox, начальная схема БД и полная цепочка миграций. |
| `lcp/` | WebSocket-шлюз, Redis Streams, возобновление сессий, уведомления об изменениях и тесты. |
| `website/` | Исходники страницы Lurg Notes с общими компонентами и стилями из frontend. |
| `docs/` | Описание продукта, протокол E2EE, состав экспорта и результаты проверок. |
| `scripts/check-public.py` | Проверка опасных файлов, известных форматов секретов и контрольных сумм экспорта. |
| `SOURCE_MANIFEST.json` | Происхождение файлов, SHA256 и отметки об адаптации для отдельного репозитория. |

Общие реализации Lurg нужны Notes для входа, AI и подтверждения Graph-фактов. В серверной копии сохранены эти зависимости, но HTTP-маршруты админки, операций, поддержки, коннекторов и чата не подключаются. Полная историческая цепочка миграций включает таблицы других платформенных функций: удаление промежуточных ревизий сломало бы подготовку БД.

## Сборка Android

Нужны JDK 17 и Android SDK 36:

```bash
cd android
./gradlew :app:assembleDebug :app:testDebugUnitTest
```

Подробности: [android/README.md](android/README.md). Debug-ключ создаётся локальными Android-инструментами. Firebase-конфигурация необязательна для сборки; для push-уведомлений нужен собственный `app/google-services.json`. Пример структуры находится в `app/google-services.json.example`.

Клиент по умолчанию использует публичные API Lurg. Для собственного сервера настройте `LURG_DEBUG_API_URL`, `LURG_DEBUG_AUTH_URL` и `LURG_DEBUG_LCP_WS_URL` при сборке debug. Для собственного релиза дополнительно задайте application ID, production-адреса, источник обновлений и отпечаток своей подписи; release-ключи передаются через окружение или внешний signing-файл.

## Локальный сервер

Нужны Docker Engine и Docker Compose v2:

```bash
cp .env.example .env
# Заполните четыре обязательных секрета своими случайными значениями.
# Для каждого значения: python3 -c 'import secrets; print(secrets.token_hex(32))'
docker compose up --build
```

API будет доступен на `http://127.0.0.1:8000`, шлюз — на `ws://127.0.0.1:8001/connect`. PostgreSQL и Redis доступны внутри Compose. На новом пустом volume сначала применяется `server/schema.sql`, затем Alembic выполняет миграции. Для существующей БД первоначальная схема не выполняется повторно.

API-ключи AI, почтовая отправка Brevo и Firebase настраиваются отдельно. Для регистрации/входа с почтовым кодом требуется рабочая почтовая конфигурация. HTTPS/WSS и reverse proxy для собственного публичного сервера настраиваются владельцем. Нативный клиент требует HTTPS для удалённых сервисов; локальные UI-тесты используют отдельные эмуляторные настройки.

Ручной запуск и тесты: [server/README.md](server/README.md), [lcp/README.md](lcp/README.md). Compose описывает самостоятельное локальное окружение, не требует production-сетей Lurg и не разворачивает действующую инфраструктуру компании.

## Страница продукта

Страница продукта:

```bash
cd website
npm ci
npm run build
npm start
```


## Публикация

В папке нет рабочих `.env`, Firebase service account, keystore, данных пользователей, резервных копий, APK и каталогов сборки. Изменения для публичной копии перечислены в [docs/EXPORT.md](docs/EXPORT.md), результаты локальных проверок — в [docs/VALIDATION.md](docs/VALIDATION.md).

Перед коммитом:

```bash
python3 scripts/check-public.py
```

Проверка известных форматов секретов дополняет ручную проверку конфигурации. Лицензия пока не выбрана; добавьте согласованный вами `LICENSE` перед публикацией, если хотите явно задать условия использования. Инструкция первого push: [GITHUB.md](GITHUB.md).
