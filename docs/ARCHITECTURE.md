# Архитектура Lurg Notes

Lurg Notes состоит из нативного Android-клиента, HTTP API, шлюза LCP и продуктовой веб-страницы.

## Android

`android/` — самостоятельный Gradle-проект версии 0.5.4. Kotlin и Jetpack Compose отвечают за интерфейс; Markdown — канонический формат документа; Room хранит локальные данные. Android Keystore защищает ключи устройства. WorkManager выполняет фоновую синхронизацию. Текущий клиент не использует JavaScript bundle.

Синхронизируемый документ шифруется на устройстве до отправки. Фото пока остаются локальными. Локальная база Room и фото не имеют дополнительного прикладного слоя шифрования. Подробности: [продукт и API](LURG_NOTES.md), [E2EE v2](lurg-notes-e2ee-v2.md).

## HTTP API

`server/app/modules/notes/` содержит редакторные действия, управление заметками и E2EE v2. Общие компоненты обеспечивают Lurg ID, AI-провайдеры, подтверждение Graph-фактов, регистрацию push-токенов и доставку уведомлений об обновлениях.

`server/app/main.py` подключает Identity, Graph, Notes и App API. Модуль чата остаётся зависимостью для функций извлечения кандидатов Graph; его HTTP-маршруты не подключаются. Административные, операционные, support и connector HTTP API также не подключены.

Базовая схема находится в `server/schema.sql`. Она применяется перед Alembic. Полная цепочка из 27 миграций сохраняет предыдущие платформенные ревизии, от которых зависят таблицы Notes. Инициализатор `server/scripts/init_database.py` отказывается работать с непустой схемой.

## Синхронизация

Зашифрованные документы, ревизии и tombstones передаются через HTTP. Изменение документа и запись события в transactional outbox происходят атомарно. Publisher отправляет событие в Redis Stream.

Шлюз `lcp/` доставляет привязанные к владельцу invalidation-события через WebSocket. Открытый Android-клиент получает `notes.events` и запускает HTTP pull. Polling и WorkManager остаются резервными механизмами. LCP сохраняет последовательности, ACK и состояние возобновления соединения; очереди ограничены временем хранения и настройками Redis.

## AI и Graph

AI получает выбранный текст только после явного действия и согласия пользователя. Предложенное изменение текста применяется пользователем. Извлечение Graph-фактов создаёт кандидатов, которые требуют отдельного подтверждения; обычное редактирование и синхронизация не добавляют факты автоматически.

## Страница продукта

`website/` — отдельный Next.js-проект с лендингом Notes, общими компонентами и стилями Lurg. Веб-редактора заметок здесь нет.

## Внешние службы

Для собственного окружения нужны PostgreSQL с pgvector и Redis. AI, почтовая регистрация Brevo и Firebase настраиваются своими ключами. Compose описывает локальную связку; инструкции сборки и запуска находятся в README соответствующих компонентов.
