# Публикация исходников на GitHub

Эта папка предназначена для отдельного репозитория. Выполняйте команды из неё: соседний рабочий каталог содержит другие продукты и локальные настройки.

## Проверка файлов

Нужен Python 3.10 или новее. Из корня подготовленной папки:

```bash
python3 scripts/check-public.py
```

Проверка запрещает локальные конфиги, ключи подписи, базы пользователей, резервные копии, сборки, зависимости и симлинки. Она ищет известные форматы секретов, не печатая их значения, и сверяет каждый экспортированный файл с `SOURCE_MANIFEST.json`.

Результат должен начинаться с `OK`. Если есть `FAIL`, исправьте перечисленные файлы и запустите проверку повторно. После намеренного изменения исходников нужно обновить манифест с новым SHA256; не обновляйте его лишь для сокрытия неожиданного изменения.

Когда рядом доступен исходный монорепозиторий, можно дополнительно сверить исходные файлы:

```bash
python3 scripts/check-public.py --verify-sources --source-root ..
```

Автоматическая проверка распознаёт известные форматы и не заменяет просмотр содержимого перед публикацией. `google-services.json.example` и примеры конфигурации содержат только плейсхолдеры. Реальные Firebase-конфиги, service account, keystore, `.env` и настройки SDK остаются локальными.

## Лицензия

Выберите условия использования кода и добавьте соответствующий файл `LICENSE` до публикации, если хотите разрешить его использование и распространение. Лицензия не выбрана автоматически. Публичная доступность репозитория сама по себе не предоставляет такие разрешения.

При добавлении файла включите его в манифест и снова выполните проверку.

## Отдельный репозиторий

На GitHub создайте пустой репозиторий, например `lurg-notes`, с нужной видимостью. README, `.gitignore` и лицензию на сайте пока не добавляйте: используйте подготовленные локальные файлы.

Из корня этой папки:

```bash
git init -b main .
test "$(git rev-parse --show-toplevel)" = "$(pwd -P)"
python3 scripts/check-public.py
```

Продолжайте, только если `test` завершился успешно, а проверка вывела `OK`. Это подтверждает, что корнем Git является именно подготовленная папка.

```bash
git add -- .
git status --short
git diff --cached --stat
```

Просмотрите список: должны присутствовать исходники, документация, конфигурации с примерами и манифест. Затем создайте коммит:

```bash
git commit -m "Publish Lurg Notes source"
```

Возьмите URL нового репозитория со страницы GitHub, кнопка **Code**, и подставьте его вместо примера:

```bash
git remote add origin https://github.com/YOUR_ACCOUNT/lurg-notes.git
git push -u origin main
```

При последующих изменениях обновляйте манифест, запускайте проверку и просматривайте изменения перед коммитом. Не выполняйте `git add` из соседнего рабочего каталога и не копируйте в публичную папку файлы с реальными учётными данными.
